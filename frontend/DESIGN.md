# HackAlem — дизайн и handoff фронтенда

## Макеты

[Открыть дизайн в Figma](https://www.figma.com/design/ataoiYMVAWfGAQKtbvpTbu). Страница «01 · Экраны» содержит редактируемые варианты текущего React-интерфейса: десктоп с 48-часовым демо-прогнозом, десктоп с 24-часовым демо-прогнозом, десктоп при ошибке API и мобильный 48-часовой демо-экран (396 px). Страница «02 · Спецификация» описывает сценарии, поля, достоверность данных и состояния. Варианты отображают пример интерфейса, а не реальные результаты модели.

Макеты получены из работающего фронтенда. При расхождении после будущих изменений кода поведение и поля сверять с `frontend/src/` и `docs/api-contract.md`; контракт редактирует интегратор.

## Минимальный сценарий показа

1. Открыть интерфейс: по умолчанию выбраны 31 января 2026, 12:00 UTC, горизонт 48 часов и режим «Демо». Бейдж и баннер прямо говорят, что кривые синтетические.
2. Показать два синхронизированных почасовых графика: `turbine-1` и `turbine-2`, диапазон нормализованной активной мощности `[0,1]`, 48 точек на каждый ряд. Дополнительные погодные показатели показывать только при наличии в данных.
3. Показать источник погоды, модель, время погодного запуска, время отсечения обучения, идентификатор запуска и предупреждения. В демо эти поля также тестовые.
4. Выбрать 24 часа и пересчитать. До пересчёта виден признак устаревших данных; после — 24 точки на график.
5. При работающем backend переключиться на «Backend API», выполнить запрос и перейти к следующему ежедневному выпуску. Для двух API-запусков сравниваются только общие будущие часы. Если backend не готов, показать объяснимую ошибку и действие «Повторить», не выдавая демо за результат API.
6. Указать, что январская диагностическая таблица — отдельный исследовательский отчёт с двумя предположениями о часовом поясе CSV; это не качество февральского прогноза.

## Состояния и взаимодействия

| Состояние | Что видно и что происходит |
| --- | --- |
| Демо по умолчанию | Янтарный бейдж, баннер «не реальный прогноз», две тестовые кривые. Демо остаётся явно отмеченным на всех размерах экрана. |
| Изменены параметры | Пока пересчёт не выполнен, показывается подсказка об устаревшем результате. Подпись числа точек относится к отображаемому прогнозу, а не к новому выбору. |
| Загрузка | Параметры и кнопки временно недоступны, на кнопке индикатор, графики приглушены. |
| Успешный API-ответ | Данные появляются только после проверки контракта; метаданные происхождения и предупреждения остаются видны. |
| Ошибка API/сети/контракта | Сообщение `role="alert"` и кнопка «Повторить». Предыдущий результат остаётся с прежней меткой происхождения; выбор API сам по себе не превращает демо-кривые в реальные. |
| Сравнение двух выпусков | Только для валидных API-прогнозов с общими будущими часами: среднее изменение, средний размер пересмотра, самый изменившийся час, изменение погодного входа при наличии. Это не оценка точности и не доказательство причины. |

Временная шкала охватывает ежедневные выпуски с 31 января по 28 февраля 2026. Кнопки предыдущего и следующего выпуска останавливаются на границах; нестандартный час выпуска поясняется отдельно. Время всюду подписано как UTC.

## Данные и границы достоверности

Источник полей — [`docs/api-contract.md`](../docs/api-contract.md). Запрос `POST /api/forecast/run` передаёт `issue_time_utc` в ISO-8601 с `Z` и `horizon_hours` 24 либо 48. Ответ содержит `run_id`, `issue_time_utc`, `training_cutoff_utc`, `weather.source`, `weather.model`, `weather.run_time_utc`, две турбины с `id` и `hourly[]`, а также `analysis[]` и `warnings[]`.

У каждой турбины должны быть ровно 24/48 непрерывных почасовых записей с `valid_time_utc` и `predicted_normalized_power` в `[0,1]`. Фронтенд проверяет ответ перед показом. Погодные поля внутри почасовых точек могут быть дополнительными; не рисовать вымышленные значения, если их нет. Обучение и погодный выпуск не должны использовать будущую информацию относительно выбранного выпуска.

Не показывать MW/MWh: номинальная мощность неизвестна. Окна низкой мощности и эквивалент полных часов — подсказки оператору на основе показанного ряда, не команда на диспетчеризацию. Фактических данных за февраль нет, поэтому февральская точность не заявляется. Часовой пояс исходного CSV организатором не подтверждён; январские MAE в интерфейсе явно обозначены как сценарные. Любое новое численное утверждение должно происходить из данных и кода.

## Визуальные правила

- Шрифт интерфейса — Inter; моноширинный стек используется для дат, времени, осей и числовых показателей.
- Фон `#f4f7f6`, основной текст `#17373b`, основная кнопка `#174f4c`; первая турбина — бирюзовая линия `#278f7d`, вторая — синяя `#577dc0`. Цвет дополняется текстовыми подписями, а не служит единственным носителем смысла.
- Основная ширина контента — до 1184 px. На широком экране графики в двух колонках; промежуточная адаптация начинается при 900 px, одноколоночная — при 640 px. Мобильный макет — 396 px.
- Карточки — белые, с тонкой нейтральной рамкой и радиусом порядка 12–15 px. Демо-предупреждение — тёплое янтарное, ошибка — красное с текстом действия. Фокус поля видим с клавиатуры; движение снижается при `prefers-reduced-motion`.
- Не скрывать на мобильном ни происхождение прогноза, ни единицы, ни предупреждения. Графики идут последовательно, каждый со своей подписью и количеством точек.

## Проверка перед демонстрацией

- `npm --prefix frontend ci`, затем `npm --prefix frontend run lint` и `npm --prefix frontend run build`.
- Открыть 48- и 24-часовой демо-сценарии на десктопе и при ширине около 396 px; убедиться, что оба ряда, подписи UTC, бейдж демо и предупреждения читаемы, а основные секции не переполняются горизонтально.
- При доступном backend проверить валидный `POST /api/forecast/run` на 31 января 2026, 12:00 UTC, 48 ч, затем следующий выпуск и сравнение. Если backend не доступен, не считать этот пункт пройденным: проверить только видимую ошибку и повтор.
- Протестировать смену горизонта до пересчёта, состояние загрузки и отсутствие ложных MW/MWh, февральского MAE или выполненных действий оператора.

## Известное ограничение макетов

В Figma зафиксированы демо и ошибка API; экран успешного подключения к реальному backend не показан, пока не получен подтверждённый контрактный ответ. Нативный календарный контрол браузера может выглядеть иначе в Figma и на разных платформах; его значение и поведение задаёт работающий интерфейс.
