# HackAlem — фронтенд прогноза ветропарка

React-интерфейс показывает почасовую нормализованную активную мощность для `turbine-1` и `turbine-2`. Графики строятся нативным SVG, поэтому отдельная библиотека графиков не нужна.

Дизайн и передача команде: [экраны и спецификация в Figma](https://www.figma.com/design/ataoiYMVAWfGAQKtbvpTbu) · [подробные правила интерфейса](./DESIGN.md).

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev
```

Откройте адрес Vite из вывода терминала. Сборка для проверки:

```powershell
npm --prefix frontend run build
```

## Режимы

- **Демо** включён при открытии страницы. Данные синтетические и прямо помечены как тестовые; они не являются прогнозом, результатом модели или оценкой точности.
- **Backend API** отправляет `POST /api/forecast/run` с `issue_time_utc` и `horizon_hours`. По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8000`.

Для другого адреса backend скопируйте `.env.example` в `.env` (`Copy-Item frontend/.env.example frontend/.env`) и измените `VITE_API_PROXY_TARGET`; либо задайте `VITE_API_BASE_URL` для прямого вызова API. `.env` исключён из Git, секреты в этих переменных не нужны. После изменения env перезапустите Vite.

API-режим требует работающий backend и контракт из [`../docs/api-contract.md`](../docs/api-contract.md). Интерфейс проверяет время выпуска, отсечение обучения, происхождение погоды, ровно две турбины, непрерывные почасовые точки и диапазон прогноза `[0, 1]`; некорректный ответ не отображается как успешный. До подключения backend используйте демо-режим.

## В интерфейсе

- Выбор времени выпуска с явной зоной UTC и горизонта 24/48 часов.
- Два синхронных по времени графика, отметка количества точек и диапазон `[0, 1]`.
- Погодные входы `forecast_wind_speed_ms` и `forecast_temperature_c` доступны на каждой почасовой точке графика; средние за горизонт показаны рядом.
- Сценарные окна низкой мощности, их порог и эквивалент часов полной нагрузки отображаются как подсказки оператору, а не как команда на диспетчеризацию или MWh.
- Повторный расчёт, переход по ежедневным выпускам сценария, состояния загрузки и ошибки. Между API-выпусками сравниваются только общие часы: среднее изменение, самый пересмотренный час и изменение погодного входа.
- Источник и запуск погодной модели, отсечение обучения, анализ и предупреждения из API.
- Отдельно показана опубликованная десятивыпускная январская диагностика с двумя сценариями часового пояса. Это условные значения из отчёта команды, а не результат демо-кривых, не февральская точность и не официальный benchmark.

## Ограничения данных

Это интерфейс для демонстрации сценария. Перед показом реального результата подключите API и официальный набор данных. По материалам команды CSV заканчивается 31 января; февральская точность пока не измерена. Интерфейс не выводит MW/MWh и не придумывает численные оценки точности.
