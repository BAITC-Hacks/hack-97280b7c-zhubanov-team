# Запуск Wind Farm Forecast

Текущий кейс — прогнозирование выработки двух ветротурбин. Нужны Python 3.12, Node.js 22.12+ из ветки 22 и два CSV организаторов.

## Установка из корня репозитория

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm --prefix frontend ci
```

Поместите CSV в `data/input/turbine-1.csv` и `data/input/turbine-2.csv`. Ссылки и соответствие турбин указаны в README. Исходные данные остаются локально.

```powershell
.\start_hackalem.ps1 -SourceTimezone UTC
```

Откройте http://127.0.0.1:5173. Выберите «Backend API» и нажмите «Пересчитать прогноз». При запуске интерфейс показывает явно помеченный синтетический пример; реальный прогноз появляется после успешного запроса. Кнопка «Следующий» делает новый ежедневный выпуск и показывает сравнение общих часов.

Часовой пояс CSV организаторами не задан. `UTC` и `Asia/Almaty` — разные сценарии; второй выбирается через `-SourceTimezone Asia/Almaty`. Путь к уже скачанным CSV можно передать через `-DataDir 'C:\путь\к\csv'`. При неоднозначном местном времени соответствующие строки исключаются и учитываются в отчёте аудита.

Для предварительной проверки путей и зависимостей добавьте `-CheckOnly`. Для остановки используйте Ctrl+C. Запускатор не устанавливает пакеты и не скачивает исходные CSV. Запрос прогноза получает архивную погоду из Open-Meteo либо использует локальный кеш; для первого получения погоды нужен интернет.

Если порт занят, остановите свой ранее запущенный сервер или задайте `-ApiPort 8001 -UiPort 5174`. Запускатор не завершает чужие процессы. Адрес API для Vite настраивается автоматически. Логи бэкенда находятся в `outputs/backend.stdout.log` и `outputs/backend.stderr.log`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
npm --prefix frontend run lint
npm --prefix frontend run build
```

GitHub Actions выполняет те же синтетические тесты, lint и сборку. Реальный прогон дополнительно требует CSV организаторов и архивных погодных прогнозов.

## Необязательные ноутбуки

Подготовительные ноутбуки перенесены в `notebooks/legacy/`. Они не заменяют текущие модули `forecast/` и не оценивают качество февральского прогноза. Установка и запуск:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-notebooks.txt
.\start_notebook.ps1
```

API-ключи из `.env.example` нужны только для необязательных LLM-экспериментов. Для работающего прогноза они не нужны. Февральских фактических данных нет; точность на февраль не заявляем.
