## Подготовка компьютера

Выполните установку по [INSTALL.md](../../INSTALL.md), скачайте оба CSV по ссылкам [README](../../README.md#6-данные-и-внешние-сервисы). Команды ниже выполняются из корня репозитория в PowerShell.

```powershell
.\start_hackalem.ps1 -SourceTimezone UTC -CheckOnly
.\start_hackalem.ps1 -SourceTimezone UTC
```

Откройте http://127.0.0.1:5173. Это локальный адрес, доступный только на компьютере запуска. Если порты заняты, используйте `-ApiPort 8001 -UiPort 5174` и откройте http://127.0.0.1:5174. Не запускайте второй экземпляр на тех же портах.

UTC — выбранный для показа сценарий, а не подтверждённый часовой пояс CSV.

## Подготовка погоды до отключения интернета

Сохраните все 58 архивных прогнозов: 29 ежедневных выпусков для двух турбин. Скрипт использует существующий погодный клиент и прекращает работу при ошибке.

```powershell
$demoFirstDay = [datetime]::new(2026, 1, 31)
for ($demoDay = 0; $demoDay -lt 29; $demoDay++) {
    $demoIssue = $demoFirstDay.AddDays($demoDay).ToString('yyyy-MM-dd') + 'T12:00:00Z'
    foreach ($demoTurbine in @('turbine-1', 'turbine-2')) {
        & .\.venv\Scripts\python.exe -m backend.weather $demoIssue $demoTurbine --hours 48 | Out-Null
        if ($LASTEXITCODE -ne 0) { throw "Weather preparation failed: $demoIssue / $demoTurbine" }
    }
}
```

Кэш находится в `data/cache/weather/`. Он покрывает выпуски с **31 января по 28 февраля 2026, в 12:00 UTC**, горизонты 24 и 48 часов. Другие часы выпуска могут потребовать дополнительных погодных запусков.

Сохраните резервную копию папки погоды отдельно от Git. На компьютере выступающего также должны оставаться CSV, `.venv` и `frontend/node_modules`. После отключения Wi-Fi вручную повторите первые два выпуска. Проверки без сетевого обращения к погодному клиенту не заменяют проверку всего ноутбука с отключённой связью.

## Основной показ

1. Выбрать **Backend API**, выпуск **31.01.2026 12:00 UTC**, горизонт **48 ч** и нажать **Пересчитать прогноз**.
2. Дождаться завершения загрузки. Показать две серии по 48 точек и исчезновение сообщения об изменённых параметрах.
3. В разделе **Как получен прогноз** показать ECMWF IFS, погодный запуск **31 января 00:00 UTC**, последнюю обучающую запись и сценарий времени CSV. Буфер 12 часов — допущение о доступности.
4. Нажать **Следующий**. Для выпуска **1 февраля 12:00 UTC** показать **24 общих часа**.
5. В UTC-сценарии крупнейший пересмотр первой турбины для **2 февраля 11:00 UTC**: нормализованная мощность с **0.082** до **0.565**, прогноз ветра с **4.24** до **8.18 м/с**. Это изменение входов и результата, не оценка точности и не причинный эксперимент.
6. Показать **Скачать CSV** и **Паспорт JSON**. В CSV текущего 48-часового выпуска 96 строк. Если браузер не сохраняет файл, открыть **Показать содержимое файла**.
7. Назвать ограничения: неизвестный часовой пояс CSV, неподтверждённое время публикации погоды, отсутствие февральских фактических значений и номинальных мощностей турбин.

## Отдельный показ автоматического контроллера

```powershell
.\.venv\Scripts\python.exe -m forecast.agent --source-timezone UTC --watch --max-checks 2 --poll-seconds 1 --output-dir outputs/demo-agent
```

Используйте свою папку результатов для каждого процесса. Первый проход должен выдать `forecast_published`, второй при неизменных входах — `unchanged`. `latest.json` указывает на последнюю успешную версию, `events.jsonl` содержит реальные события. Проверки изменения входов и восстановления после ошибки описаны в [agent-verification.md](../agent-verification.md). Не изменяйте исходные CSV организаторов ради показа.

Контроллер следит за содержимым **локальных** CSV и выбранных погодных файлов. Он не подписывается на новые онлайн-выпуски. Браузер работает через отдельный API и не обновляется автоматически от публикации CLI: в нём нужно заново запросить прогноз.

## Перед выступлением

- Подключить питание и проверить читаемость графиков на экране презентации.
- Держать слайды, результаты и исходники локально.
- При ошибке показать её явно. Сохранённый прогноз обозначить как результат предыдущего запуска, синтетическое демо — как тестовые данные.
- Запустить `python submission/verify.py` для проверки месячных файлов.

Результаты повторной технической проверки: [verification.md](verification.md).
