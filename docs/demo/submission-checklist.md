## Перед отправкой

1. Убедиться, что нужный PR объединён в `main` и итоговый коммит доступен жюри.
2. Повторить сценарий двух выпусков из [инструкции демонстрации](README.md).
3. Проверить месячные выгрузки, наличие README, слайдов и ограничений.
4. Сверить актуальные требования и дедлайн по [инструкции организаторов](https://drive.google.com/file/d/105Rnhzg3Q5tKjfGZIddRqY13kmq_w4r_/view) и сообщениям команды. Порядок подачи описан в [разделе 11 README](../../README.md#11-развёрнутая-версия-и-материалы).
5. Отправить решение на платформе и убедиться в подтверждении отправки. Git push и создание PR сами по себе форму сдачи не отправляют.

Локальные адреса `127.0.0.1` не являются публичной развёрнутой версией. Сырые CSV, погодный кэш, окружение Python, зависимости интерфейса и секреты остаются вне Git. Для воспроизведения другим человеком нужны CSV по ссылкам README и погодный API либо отдельно подготовленный кэш.

## Что сказать жюри

- Прогноз имеет почасовой горизонт 24 или 48 часов для двух турбин.
- Модель использует только историю до времени выпуска.
- В прогнозе сохранены источник погоды, время запуска и границы обучения. Буфер 12 часов — допущение о доступности.
- Пересчёт использует обновившиеся входы. CLI наблюдает локальные файлы, браузер требует нового запроса.
- Часовой пояс CSV неизвестен. Январские метрики сценарные и исследовательские.
- Февральских фактических значений и номинальных мощностей нет. Февральскую точность, MW/MWh и экономический эффект не заявляем.
- Решения по эксплуатации принимает человек.
