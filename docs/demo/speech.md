# Речь к пяти слайдам

Ориентир: 90–120 секунд речи, затем демонстрация приложения. Продолжительность проверьте вслух.

## 1. Задача

WindTrace AI прогнозирует почасовую нормализованную мощность двух ветротурбин на сутки или двое. Система использует историю работы турбин и архивные прогнозы погоды, затем позволяет повторить расчёт для следующего дня.

## 2. Модель и автоматический цикл

Для каждой турбины строим свою кривую мощности по историческому ветру с температурной поправкой. Обучение ограничено временем выпуска. Система получает архивный запуск ECMWF через Open-Meteo и сохраняет происхождение данных. Отдельный контроллер замечает изменения локальных входных файлов и автоматически публикует новую проверенную версию. При ошибке он сохраняет прошлый результат.

## 3. Качество

Команда проверила модель на десяти январских выпусках, всего на 960 часах двух турбин. В сценарии Asia/Almaty MAE модели составила 0.173 против 0.337 у прогноза по последним шести часам. При трактовке CSV как UTC значения составили 0.206 и 0.295. Часовой пояс организаторы не определили, поэтому оба результата являются сценарной диагностикой. Февральской точности у нас нет.

## 4. Пересчёт

Получим прогноз на 31 января и перейдём к следующему выпуску. Сравниваем только общие часы. Например, для первой турбины прогноз на 2 февраля в 11 часов изменился с 0.082 до 0.565. Для того же часа прогноз ветра изменился с 4.24 до 8.18 метра в секунду. Оператор видит сам пересмотр и обновившиеся входные данные.

## 5. Польза

Система помогает заметить ожидаемые окна низкой мощности и выбрать часы для дополнительной проверки. Решение принимает оператор. Мы подготовили 29 ежедневных выпусков, выгрузки с происхождением данных и запуск из локального погодного кэша. Результат можно связать с конкретным выпуском и повторить.

## Ответы на вопросы

**Почему нет февральского MAE?** Организаторы не предоставили фактическую мощность за февраль. Выгрузки содержат прогнозы, а не оценку их точности.

**Что значит 0.565?** Нормализованная активная мощность. Номинальные мощности неизвестны, поэтому перевод в MW и MWh не выполняем.

**Где agentic AI?** Детерминированный контроллер наблюдает локальные входы, решает, нужен ли пересчёт, вызывает модель, проверяет результат и публикует версию. При неизменных входах пропускает расчёт, при ошибке повторяет попытку. LLM-планировщика и управления оборудованием нет.

**Интерфейс обновляется сам?** CLI-контроллер и браузерный API разделены. Контроллер сохраняет файлы версий, а в браузере нужно запросить новый результат.

**Почему прогноз изменился?** Изменились погодный выпуск и допустимый срез истории. Интерфейс показывает различия во входах. Это объяснимое сравнение, а не причинный эксперимент.

**Как исключаете будущую погоду?** Берём архивный запуск, инициализированный минимум за 12 часов до времени выпуска. Буфер является допущением, фактические метки публикации не подтверждены.

**Работает ли без интернета?** Подготовленные даты работают из кэша. Для отсутствующего погодного запуска нужен интернет.

**Почему GitHub Actions красный?** Последние задания не запускались из-за блокировки биллинга аккаунта владельца. Результаты локальной проверки приведены отдельно. Актуальный статус нужно смотреть в GitHub Actions.
