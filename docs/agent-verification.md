# Проверка пересчёта и соответствия кейсу

Проверено локально 23 сентября 2026 года. Контроллер `forecast.agent` — детерминированный цикл наблюдения и действий, без LLM-планировщика. Он автоматически обрабатывает изменения **локальных** входов в заданном историческом периоде. Это не промышленный сервис и не подписка на поступающие онлайн-выпуски погоды.

## Проверяемый цикл

1. Рассчитать SHA-256 двух CSV и погодных файлов для выбранного расписания.
2. Если входы не изменились с последней успешной версии, пропустить расчёт.
3. Если это первый запуск или содержимое изменилось — проверить CSV, получить недостающие архивные погодные запуски, обучить модель на допустимой истории, сформировать и проанализировать прогнозы.
4. Проверить временные границы, непрерывность часов, диапазон мощности и стабильность входов за время расчёта.
5. Сохранить новую версию JSON/CSV с паспортом; обновить указатель `latest.json` только после успешного экспорта. Записать причину и величину пересмотра по совпадающим точкам.
6. При ошибке записать событие, сохранить прошлый успешный результат и повторить попытку на следующем цикле наблюдения.

`events.jsonl` содержит реальные события процесса, а не заранее заданную анимацию. Он не является подробной трассировкой каждого HTTP-запроса. Неизменное состояние не добавляет строки в журнал. У каждого процесса должна быть своя папка результатов; после перезапуска выполняется новый начальный расчёт.

Проверка загрузки отсутствующей погоды в автоматическом тесте использует подставной HTTP-ответ. Реальный прогон контроллера использовал ранее скачанный погодный кеш; нового независимого подтверждения публикации архивной погоды он не даёт. CSV организаторов при проверках не изменялись.

Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q

.\.venv\Scripts\python.exe -m forecast.agent --source-timezone UTC --watch --max-checks 2 --poll-seconds 1 --output-dir outputs/agent-check
```

## Что остаётся допущением

- Инициализация погодной модели за 12 часов до выпуска не доказывает фактическое время публикации. Ограничение теперь явно написано и в исходном ответе API, и в интерфейсе.
- Часовой пояс CSV не подтверждён. В репозитории сохранены оба сценария, без выбора «правильного» по меньшей ошибке.
- Исправление исторических входов сегодня меняет воспроизведение; нельзя выдавать такую версию за прогноз, реально выпущенный в прошлом.
- Новые онлайн-выпуски погоды контроллер самостоятельно не обнаруживает; отслеживаются выбранные локальные файлы. Соседние исторические даты обрабатываются автоматически внутри пакетного расчёта.
- Браузерный интерфейс использует отдельный API; публикация CLI-версии не обновляет открытый график автоматически.
- Февральских фактических значений нет. Проверки структуры и пересчёта не подтверждают точность прогноза или оценку жюри.

Проверки GitHub Actions ранее не запускались из-за ограничения оплаты аккаунта владельца репозитория. Локальное прохождение тестов не заменяет успешный hosted CI.
