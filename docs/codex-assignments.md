# Готовые задания для трёх Codex

Каждый участник открывает **свою копию** `https://github.com/BAITC-Hacks/hack-97280b7c-zhubanov-team`, обновляет `main`, читает `AGENTS.md`, `docs/api-contract.md` и `docs/four-hour-sprint.md`, затем запускает только своё задание ниже. В конце каждого часа — commit и push собственной ветки, ссылка на прогресс команде. Не передавайте API-ключи в чат или Git. Сырые CSV положите локально в `data/input/` по `README.md`; папка исключена из Git.

**Текущий статус:** участник ML уже реализовал `forecast/` и проверил полный цикл из 29 выпусков. Фронтенду и бэкенду начинать со свежего `main`; бэкенду использовать [ML handoff](ml-handoff.md) и не переписывать прогнозный модуль. Блок задания участника 3 ниже сохранён как исходное распределение, повторять его не требуется.

## Участник 1 — фронтенд и дизайн

> Ты Codex фронтенд-разработчика команды HackAlem. Работай в ветке `feat/frontend` и только в `frontend/`, кроме согласованных мелких правок README. Прочитай `AGENTS.md`, `docs/api-contract.md`, `docs/four-hour-sprint.md`. Сделай понятный интерфейс прогноза двух ВЭС: два почасовых графика нормализованной мощности [0,1], выбор UTC-времени выпуска, переключатель 24/48 часов, карточку источника погоды и времени модельного запуска, кнопку повторного расчёта, загрузку и объяснимую ошибку. Сначала подключи локальный JSON по контракту, затем реальный `POST /api/forecast/run`. Отмечай тестовые значения как тестовые. Не показывай MW/MWh: номинальная мощность неизвестна. Проверь вид в браузере, запиши точные команды запуска. Каждый час фиксируй работающий этап коммитом и push в свою ветку; создай PR в `main` не позже второго часа. Не правь `backend/` и `forecast/` без согласования.

## Участник 2 — бэкенд и интеграция

> Ты Codex бэкенд-разработчика и интегратора HackAlem. Работай в ветке `feat/backend-api`, владеешь `backend/`, настройкой запуска и `docs/api-contract.md`. Прочитай `AGENTS.md`, `docs/four-hour-sprint.md` и текущий контракт. Используй уже существующий `backend/weather.py` — он получает архивный погодный запуск для каждой из двух турбин и кэширует результат. Реализуй загрузку `data/input/turbine-1.csv` и `turbine-2.csv`, явную настройку часового пояса исходных наивных временных меток, часовую агрегацию и проверку пропусков. Реализуй `POST /api/forecast/run` и затем `POST /api/forecast/rolling` по контракту. Поставь временной барьер: обучение и входные наблюдения не позже времени выпуска; погодный запуск не позже допустимой границы. Модуль `forecast/` будет добавлен третьим участником — сначала используй явно обозначенный fixture, затем подключи его чистую функцию. Верни 24/48 будущих часов для каждой турбины и метаданные происхождения погоды. Нужны точные команды запуска, одна проверка полного ответа и обработка ошибки внешнего API. Каждый час commit + push; PR в `main` не позже второго часа. Не заменяй архивный прогноз фактической погодой.

## Участник 3 — модель и проверка (эта сессия)

> Ты Codex разработчика прогнозной модели HackAlem. Работай в ветке `feat/forecast-core` и в `forecast/` плюс узкие тесты. Прочитай `AGENTS.md`, `docs/four-hour-sprint.md`, `docs/api-contract.md`. На 10-минутной истории каждого турбины обучи быструю эмпирическую кривую мощности по измеренной скорости ветра, с честным временным cutoff и выходом [0,1]. Экспортируй функцию предсказания, принимающую turbine ID, погодные часы из `backend/weather.py`, cutoff UTC и явный часовой пояс CSV. Зафиксируй, какую из погодных скоростей (10/100 м) используешь и почему это допущение. Проверь модель на январских исторических выпусках с архивной погодой, не используя наблюдения после cutoff для обучения; укажи MAE, интервал и предположенный часовой пояс. Не объявляй точность за февраль без фактических данных. Каждый час commit + push; PR в `main` не позже второго часа.

## Единый формат часового отчёта

`Час 1/2/3/4 | ветка и ссылка на коммит/PR | работает: ... | проверено: ... | блокер: ... | следующий час: ...`

Интегратор просматривает все три отчёта, проверяет совместимость JSON, сливает готовые PR и запускает общую демонстрацию. Если ветка ещё не готова к слиянию, её часовой push всё равно обязателен.
