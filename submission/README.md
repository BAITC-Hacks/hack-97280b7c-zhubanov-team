# WindTrace AI: результаты для проверки жюри

Эта папка содержит готовые **прогнозы**, а не фактическую выработку. Проверка файлов не требует исходных данных, ключей, интернета или сторонних Python-библиотек.

Из корня репозитория выполните:

```powershell
python submission/verify.py
```

На Windows с установленным Python 3.12 также можно использовать `py -3.12 submission/verify.py`.

## Два сценария времени

| Папка | Интерпретация времени исходных CSV | Содержимое |
|---|---|---|
| [monthly-utc](monthly-utc/) | UTC | `forecasts.csv` и `manifest.json` |
| [monthly-almaty](monthly-almaty/) | Asia/Almaty | `forecasts.csv` и `manifest.json` |

Организаторы не указали часовой пояс исходных CSV. **Ни один сценарий не подтверждён как правильный.** Это анализ чувствительности к допущению, а не выбор победившей модели по официальному результату.

В каждом наборе:

- Две турбины, 29 ежедневных выпусков с 31 января по 28 февраля 2026 года, время выпуска 12:00 UTC.
- Каждый выпуск содержит 48 последовательных часовых прогнозов для каждой турбины; всего 2 784 строки. Соседние выпуски перекрываются, поэтому это не 2 784 уникальных часа.
- Для каждой турбины покрыты все 672 часа февраля: с `2026-02-01T00:00:00Z` по `2026-02-28T23:00:00Z`. Файлы также содержат часы за пределами февраля из-за горизонта 48 часов.
- Цель — нормализованная активная мощность в диапазоне [0,1], без единиц. Это не МВт или МВт·ч, суммировать значения как энергию станции нельзя.
- Погода — архивные выпуски Open-Meteo Single Runs API, модель ECMWF IFS, ветер на высоте 100 м как допущение. Используется эмпирическая кривая мощности отдельно для каждой турбины.

## Что проверяет скрипт

`verify.py` сверяет SHA-256 CSV с паспортом, число строк, обе турбины, 29 дат выпуска, непрерывный горизонт 48 часов, диапазон мощности, полное покрытие февраля и заявленные временные границы. Для погоды проверяется `weather_run_utc + 12 часов <= issue_time_utc`; для обучения — `latest_training_time_utc <= training_cutoff_utc <= issue_time_utc` и окончание исходной истории 31 января с учётом сценария времени.

`training_cutoff_utc` — разрешённая граница обучения при выпуске. Фактически последняя использованная дата хранится отдельно в `latest_training_time_utc`; февральские выпуски не означают наличие февральских наблюдений мощности.

**Проверка временных меток не доказывает историческую публикацию прогноза погоды.** Буфер 12 часов — явное допущение доступности; реальные моменты публикации архивных выпусков не подтверждены. Проверка также не переобучает модель и не подтверждает отсутствие утечки независимо от заявленной метаинформации.

Фактическая мощность за февраль не предоставлена, поэтому здесь нет февральской MAE и официального балла. Январские диагностические сравнения из основного README — предварительная оценка на другом периоде, не результат проверки этих файлов и не официальный результат соревнования.

## Происхождение и воспроизведение

Файлы скопированы без изменения байтов из подготовленных локальных экспортов `outputs/submission-forecasts/monthly-utc/` и `outputs/submission-forecasts/monthly-almaty/`. В паспорте сохранены время экспорта, SHA-256 экспортированного CSV и `input_sha256` исходного JSON результата. Исходный JSON в эту папку не включён, поэтому его хеш здесь не проверяется.

`exporter_git_revision` фиксирует ревизию кода **экспортёра** на момент выгрузки. Это не подтверждение ревизии кода, которым первоначально был рассчитан исходный прогноз, и не дата его исторического выпуска.

В этой папке разрешённый состав ограничен четырьмя файлами результатов/паспортов, этим описанием, проверочным скриптом и `.gitattributes`. Последний отключает преобразование переводов строк в CSV/JSON при работе Git, чтобы контрольные суммы оставались одинаковыми на Windows и Linux. Исходные CSV организаторов, погодный кеш, ключи и `.env` сюда не включены. Наличие результатов в репозитории не устанавливает отдельную лицензию на исходные данные.

Источники и команды повторного расчёта описаны в [основном README](../README.md); [условия кейса](https://docs.google.com/document/d/1Fn5IJoj87Fx7IAknG26zkfX8c0eq7feCujd0m66PCgY/edit) остаются первичным описанием задания.
